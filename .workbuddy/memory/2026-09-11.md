## 卡了 20 分钟的四个根因（都已解决，是环境问题不是规则问题）

1. **沙箱拦住浏览器**：Bash 沙箱里 `chromium.launch()` 直接 SIGTERM / `Permission denied` / `spawn UNKNOWN` → 该步骤必须 `dangerouslyDisableSandbox: true`。
2. **Playwright 1.48 与浏览器版本不匹配**：全局 playwright 要 chromium-1140，机器上只有 **chromium-1228** → 用 `executablePath` 指向 `ms-playwright\chromium-1228\chrome-win64\chrome.exe`，别去装新浏览器。
3. **我多传了 `--force-device-scale-factor=2`**，与 `deviceScaleFactor:2` 叠乘成 4 倍 → 渲染器崩溃 `Target page, context or browser has been closed`。**只保留 dsf**。
4. **localhost 被浏览器绕过**：浏览器走系统代理，`127.0.0.1` 被绕开 → 本地图片全 404（而 CDN 图正常，极易误判"素材坏了"，我一度以为本地服务坏了，其实 `curl` 能正常拿到 89958 字节）→ 改用 **`file://` 直读磁盘**。

另外两个导致"没反应"的坑：
- **图片 `loading="lazy"`**：不进视口根本不发请求，改 src 也没用 → 截图前先统一改 `loading='eager'`。
- **无超时地等所有 `<img>` 的 Promise**：懒图不就绪时永不 resolve → 脚本静默挂起 5 分钟。改用 `Promise.race([图像Promise, 8s])` + 全局 150s 看门狗 + 每步 `fs.appendFileSync` 落盘。

## 改动 3：拖拽/粘贴图片 + 一键打包 ZIP

表单每个条目两个**拖拽区**：**产品图**（页面卡片用，可多张，第一张为主图）+ **口味信息图**（可多张，供我读字段）。支持拖拽、点击选择、**Ctrl+V 粘贴**（截图直接贴）。
「⬇ 打包下载」生成 `新品包.zip`：
- 产品图 → `extracted_images/disposable_images|pod_images/` 或 `device_colors/`（按品类自动选）
- 信息图 → `_newproduct_refs/<品名>/`（已 gitignore，我读完删）
- 配置 → `新品.json`
用户解压到项目根目录即可，无需手动改名/挪文件。

**ZIP 是手写 store 无压缩实现（零依赖）** —— CRC32 查表 + local header + central directory + EOCD，文件名带 UTF-8 flag（0x0800）。
**验证方式**：把 HTML 里的 `CRC_T/crc32/u16/u32/buildZip` 抽出来在 Node 里跑，生成 zip 后用 **Python `zipfile` 读回** → CRC 全部通过、3 个条目名与字节完全一致（含中文路径 `_newproduct_refs/秘境寻幽/口味信息.png`），说明 Windows 资源管理器 / 7-Zip 都能正常解压。
